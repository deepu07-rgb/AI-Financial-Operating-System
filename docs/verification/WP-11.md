## Scope delivered

- `aifos-connector-sdk` contract v1 with manifests, canonical party/invoice
  records, field mappings, source/preview hashes, row errors, and bounded input.
- UTF-8 CSV party and invoice import with explicit header mapping, deterministic
  money/date/currency/enums, independent invalid rows, formula-safe CSV export,
  and synthetic fixtures.
- File-only Tally XML pilot for `LEDGER` and purchase/sales `VOUCHER` records,
  strict `ENVELOPE` parsing, unsafe XML rejection, documented version matrix,
  and no Tally HTTP/credential/write-back behavior.
- SQLite schema 8 with append-only import runs, row outcomes, external links,
  `needs_review` external invoice staging, and export evidence.
- Atomic repository commit with deterministic idempotency. Valid party rows are
  imported, invalid rows retained as errors, identical records skipped, and
  external invoices staged without creating approved snapshots.
- Native source/save dialogs. Paths remain in Rust; selected bytes use a
  workspace-bound token and expire after 15 minutes; commit reparses and
  verifies the preview hash.
- Integrations UI with connector health, CSV mapping, canonical preview,
  per-row outcomes, valid-only commit, staged transactions, run history, and
  controlled CSV export.

## Safety invariants

- No API key, provider/model SDK, local model, connector credential, desktop
  HTTP permission, or external-system write capability is present.
- React supplies no filesystem path, SQL, canonical import record, import
  outcome, idempotency key, or approved-state mutation.
- Invalid rows do not block valid rows and never create a partial row record.
- Imported transaction data cannot enter approved invoice snapshots through a
  connector command; it remains `needs_review` staging.
- Every committed import/export has named local-user and append-only audit
  evidence; errors and UI messages contain no path or raw source file.
