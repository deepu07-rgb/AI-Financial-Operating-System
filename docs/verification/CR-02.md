## Scope delivered

- Inbox is now an Invoice Upload Center with a native multi-file picker,
  operating-system drag/drop, per-file outcomes, exact-duplicate policy, named
  responsible user, visible runtime readiness, and direct Review handoff.
- Schema migration 10 adds append-only ingestion batches/items/events, watched
  folder configuration and receipts, and versioned supplier extraction
  templates. Repository state is reconstructed from events rather than mutable
  progress rows.
- Processing supports visible progress, pause/resume at a safe item boundary,
  active worker cancellation, retry for failed/cancelled managed files, and
  startup recovery of interrupted batches. No ingestion command approves an
  invoice.
- The optional watched folder is chosen through a native dialog. It accepts only
  canonical regular direct-child PDF/PNG/JPEG files after a three-second
  stable-size/modified-time check, copies them to managed storage, records a
  content receipt, and stops its joined observer when disabled.
- Exact duplicates support reject, link, or keep rules. Probable duplicates show
  the matching invoice number/date/supplier/total fields and require a named
  human keep-for-Review or reject decision.
- Failed or unsupported managed documents have a manual-entry fallback. Manual
  values and lines are marked `human_entered`, contain no invented OCR boxes or
  confidence evidence, and always enter Needs Review.
- Extracted lines retain completeness, trust, source boxes, and evidence kind.
  Review explicitly says when reliable rows are unavailable instead of guessing.
- Correction evidence may become a supplier exact-label proposal after two
  corrections. Proposed/retired templates never enter a worker request; only a
  user-approved current version can influence future extraction. All versions
  and status changes are audited; prior runs remain append-only.

## Security boundary evidence

- The worker receives strict versioned JSON and canonical managed paths, verifies
  the source SHA-256, and cannot query SQLite or approve finance records.
- Python isolated mode disables user site packages. Its audit hook denies socket
  operations, unapproved child processes, and writes/renames/removals outside the
  worker job root; hostile-policy tests exercise all three denials.
- Rust serializes extraction through one worker, caps output, applies a
  120-second timeout, and kills on timeout/cancel. On Windows the child is placed
  in a kill-on-close Job Object limited to one active process and 768 MiB process
  memory.
- Decode/preprocess limits remain 20 pages and 50 megapixels. An invalid file is
  a per-file failure and does not abort import of the other selected files.
- React receives opaque IDs, filenames, states, and evidence only. Native picker,
  drop, watched-folder, managed-source, and export paths never enter the webview.

## Acceptance disposition

Acceptance gates 2 through 7 have implementation and automated/local corpus
evidence. Gate 1 cannot honestly be closed inside a source-development task:
there is no release private key or approved Windows certificate in the
repository, by design. The release operator must run the documented signing
ceremony, install that signed candidate on a clean supported Windows VM, run the
readiness probe and approved corpus, and attach the resulting artifact hashes and
VM evidence. CR-03 must not weaken or bypass this gate.

## Boundaries retained

  trusted merely because confidence is high.
- No API key, cloud OCR, network connector, LLM, telemetry, bank instruction, or
  payment execution was added.
- Operational invoice/party/payment registers remain CR-03 rather than being
  simulated inside the Upload Center.
