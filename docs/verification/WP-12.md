## Safety invariants

- No API key, provider credential, local LLM/model weight, updater private key,
  or Windows private key is part of source, React, or the installer.
- The public updater key identifies trusted release artifacts; it is not a
  secret or authentication credential.
- No update network request occurs on application launch, settings open, or
  status load. The offline installer remains the primary recovery path.
- The updater cannot accept a different host, non-HTTPS/credentialed URL,
  missing/oversized signature, missing/oversized artifact evidence, or hash/size
  mismatch. Signature failure preserves the installed version and workspace.
- A failed migration cannot commit a partial schema chain. Existing approved
  records remain in the rolled-back database and the recovery checkpoint.
- Development caches and environments are not release resources. Release
  ceilings are 1 GiB installer, 2.5 GiB runtime, and 3.5 GiB installed-product
  acceptance target.

## Production evidence still required

No public installer was generated from developer credentials. SEC-003 correctly
remains a publication gate until the owner supplies a production Authenticode
certificate, Tauri updater signing key, reviewed runtime archive/hash/licenses,
approved publisher identity, and release endpoint through the protected CI
environment. The release must then pass the clean offline Windows VM, OCR/report,
installed-size, signature/timestamp, update-failure, every-schema migration, and
rollback checks in the runbook. This is deliberate fail-closed behavior, not an
API-key requirement.
