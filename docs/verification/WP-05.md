## Scope delivered

- Exact Imported → Processing → Needs Review → Approved/Rejected → Exported
  document state policy, including the permitted Rejected → Needs Review and
  Needs Review → Processing retry paths.
- SQLite schema migration 4 with append-only document transitions, field
  corrections, and review comments plus indexes, constraints, and immutable
  triggers.
- Atomic repositories that validate current state, extraction/document binding,
  expected current field value, actor identity, and audit event.
- Render-only worker operation for bounded page previews without an OCR engine;
  Rust re-verifies the managed source hash/path before invoking it.
- Desktop commands for workspace discovery, local reviewer setup, review queue,
  case detail, preview, correction, comment, and approve/reject/reopen actions.
- Side-by-side React review route with page navigation, click-to-highlight source
  evidence, high/medium/low confidence display, correction reasons, reviewer
  controls, decision reasons, comments/tags, and immutable history.
- Keyboard-first correction and decision shortcuts that call the same validated
  commands as visible buttons.
- Deterministic approval validation for required fields, ISO date, currency,
  non-negative total, and subtotal-plus-tax agreement within 0.01 using integer
  minor units.
- ADR-0006 plus updated architecture, threat model, README, and dependency scope.
  WP-05 introduced no dependency or Tauri capability expansion.

## Requirement coverage and open gates

- FR-REV-001: the complete document state graph is implemented and tested.
  Export behavior remains intentionally absent, although Approved → Exported is
  reserved for the later export command.
- FR-REV-002: corrections preserve original, prior, new, reviewer, timestamp,
  reason, and extraction linkage as immutable evidence.
- FR-REV-003: fields are tab-addressable and correction/approval/rejection have
  documented shortcuts. Shortcuts cannot bypass a reviewer or reason.
- FR-REV-004: correction evidence is structured for pattern aggregation, but
  supplier-template proposal, explicit approval, and rollback are not yet
  implemented. This Should requirement remains a visible follow-up rather than
  silently changing extraction behavior.
- FR-REV-005: append-only comments and normalized, deduplicated tags are
  implemented.
- FR-OCR-004: selecting a field navigates to recorded page evidence and overlays
  its bounding box on a hash-verified local preview.
- FR-OCR-005: confidence tiers and warnings direct human attention; no confidence
  level auto-approves or posts a document.
- This machine still has no approved Tesseract binary/model, so a real invoice
  cannot complete OCR here. The UI reports worker failure and returns the
  document to Needs Review instead of simulating extraction.
- Extraction persistence and processing-state completion are separate
  repository transactions. Add startup reconciliation/crash injection before
  production packaging.
- Plaintext workspace storage and the worker OS sandbox remain WP-08/WP-12
  release gates.
