# WP-04 Verification Record

- Work package: WP-04 — OCR worker
- PRD references: FR-OCR-001 through FR-OCR-006; SEC-004; Sections 12, 18, 19; WP-04
- Status: Complete for the worker/protocol/adapter foundation; production OCR runtime gate remains explicit
- Date: 2026-08-04

## Scope delivered

- Python 3.12-3.14 single-job service with strict JSON protocol version 1.
- Canonical job/document UUIDs, allowed-root containment, expected SHA-256
  verification, exact media types, and unknown-field rejection.
- PDF rasterization with a 20-page limit and image decoding with a 50-megapixel
  per-page limit inside the worker process.
- Versioned preprocessing for orientation, grayscale, bounded deskew, median
  denoise, autocontrast, content crop, page segmentation, and derivative hashes.
- Replaceable OCR engine contract plus a bounded English Tesseract TSV adapter
  that reports the real engine version.
- Conservative field extraction for invoice identifiers/dates, supplier, tax ID,
  currency, subtotal, tax, total, due date, payment terms, and bank text.
- Confidence and word-level page/bounding-box sources for every emitted field;
  bank details are untrusted and line items are omitted when unreliable.
- Decimal subtotal-plus-tax validation and explicit review warnings.
- Rust worker client with one-worker desktop gate, 120-second process timeout,
  process kill, 16 MiB response cap, bounded stderr, and response token/hash
  matching.
- Schema migration 3 and append-only `ExtractionRun` repository with atomic
  completion audit; failed jobs append a document failure audit.
- Desktop commands for explicit runtime readiness and processing by validated
  workspace/document IDs. No source path crosses frontend IPC.
- Exact Python dependency register, CI Python pin, combined license report, and
  CycloneDX SBOM entries.
- ADR-0005 plus updated architecture, threat model, README, and notices.

## Requirement coverage and open gates

- FR-OCR-001: the versioned preprocessing stages and reproducible derivative
  evidence are implemented; originals remain managed and unchanged.
- FR-OCR-002: the real English CPU adapter is implemented, but this machine has
  no approved Tesseract binary/model. The runtime status correctly returns not
  ready instead of simulating OCR. Packaging and the minimum-PC performance
  benchmark remain release gates.
- FR-OCR-003: conservative fields, confidence, and source coordinates are
  implemented. Reliable multi-row line-item extraction requires the corpus
  benchmark and is intentionally not fabricated.
- FR-OCR-004: evidence is structured for click-to-highlight, but the side-by-side
  review interface belongs to WP-05.
- FR-OCR-005: low confidence, missing totals, arithmetic mismatch, bank text, and
  unreliable line items produce review warnings; approval policy belongs to
  WP-05.
- FR-OCR-006: Decimal arithmetic validation is implemented with an explicit 0.01
  tolerance and mismatch result.
- SEC-004 is only partially satisfied by canonical access, isolated process,
  one-worker concurrency, page/pixel/output/time bounds, and no network
  dependency. A Windows restricted token/Job Object or AppContainer memory cap
  is still required before hostile-document production use.
- The pypdfium2 wheel's complete embedded PDFium notices and the exact Tesseract
  build/model license texts must ship with any installer.
